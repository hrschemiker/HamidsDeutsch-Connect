# Manfaz VPN 2.25.0

This release is mostly about one bug. If your connection kept dropping and coming back on its
own every half minute, that was not your server and not your operator. It was this app, and it
is fixed.

The rest of the work follows from the same idea: the Kill Switch now gives you a way back
online that does not require finding the window first, Cloudflare clean addresses are actually
applied instead of being collected and thrown away, and pressing connect now shows you that
something is happening.

## The reconnect loop

Every thirty seconds the app checked whether the tunnel was still healthy. The check asked a
public address service for your address twice: once through the tunnel, and once outside it.
If it could not get the outside answer, it concluded the tunnel was broken and tore it down.

The outside answer travels over the ordinary, filtered path. Those services are frequently
unreachable that way, which means a healthy tunnel was being destroyed on a regular schedule
for a reason that had nothing to do with the tunnel.

Three things changed:

- Reaching an address service through the tunnel is now treated as what it is, namely proof
  that traffic leaves the machine and comes back. If the outside answer is also available the
  two are still compared and must differ, but its absence is no longer a failure.
- A single failed probe no longer triggers anything. Recovery needs three consecutive
  failures. A dead engine or a system proxy that was switched off underneath the app still
  act immediately, because those are certain.
- The same rule was applied to connecting. The app used to refuse a connection outright when
  it could not read the outside address, which on some networks meant it would not connect at
  all.

## Kill Switch

The switch itself worked. Getting back online after it fired did not, if the window was not
already in front of you, since by definition you are offline and cannot look up what happened.

- When the block engages, the app now raises its window, posts a Windows notification, and
  adds a "restore internet" entry to its tray menu.
- The choice is spelled out rather than hidden in a secondary link. One button reconnects
  through the VPN. The other lifts the block and returns normal internet, and says plainly
  that traffic will no longer be protected.
- The tray entry works with the window closed, which is the situation that matters.

## Cloudflare clean addresses

The scanner has been finding good edge addresses all along. They were never used.

The connection path checked whether a hostname resolves into Cloudflare's network, which is
the correct test and covers ordinary custom domains. The configuration builder then repeated
the check with a much narrower one that only recognised `workers.dev`, `pages.dev` and literal
Cloudflare addresses. Nearly every real configuration failed that second test, so the scanned
address was discarded.

- The second check is gone. The path that already resolved the hostname decides.
- Substituting an address no longer breaks the request. The original hostname is kept as the
  TLS server name and, for WebSocket and HTTP transports, as the Host header, which the edge
  needs in order to know where the request is going.
- Clean addresses now apply in TUN mode too. They were only ever wired into System Proxy.

## DNS

Both DNS paths were audited. Every resolver profile was compiled into an engine configuration
and validated against sing-box itself, in System Proxy and in TUN, and all of them pass.

One real problem was found and fixed in DNS only mode. If the app started and discovered that
a previously applied resolver was no longer set on every adapter, it marked DNS as off and
stopped there. Adapters that still had it kept pointing at a resolver that nothing would ever
clean up. It now restores the recorded baseline before reporting DNS as off.

The encrypted DNS fix from the previous release is worth repeating, since it was the reason
name resolution could fail inside a tunnel: the server name for encrypted queries is now taken
from the resolver you selected rather than always being Cloudflare's.

## Connecting now looks like something is happening

Pressing connect showed a strip of stage icons that was driven by whether an engine call was
in flight. The two slowest parts of connecting, validating the configuration and checking the
address, are not engine calls, so the strip disappeared for ten seconds at a time and the app
looked frozen.

There is now a progress panel that stays for the whole attempt and shows the current step, the
step number, a progress bar, the server being tried, which attempt it is when the app moves
through several servers, and a seconds counter so a slow step still visibly ticks.

## Everything else

- The tray menu is rebuilt as state changes instead of being fixed at startup.
- The development preview now ships with a sample subscription so the connection flow can be
  worked on without a real backend.
- Release builds publish a copy of the installer under a fixed name, so the download link in
  the README points at the newest build forever without being edited.

## Installing

Download `Manfaz-VPN-Setup-2.25.0-x64.exe` below and run it. Windows 10 or 11, 64 bit. Both
engines are included, so there is nothing to fetch on first launch.

Run the app as Administrator if you want TUN, the Kill Switch, or system DNS changes. Without
elevation everything else still works over System Proxy.
