# Manfaz VPN 2.22.0 — Honest Connections

This release tightens the contract between the interface and the network: Manfaz now reports a connection only after it can prove that traffic exits through a different public address.

## Highlights

- Restored **sing-box as the default engine** for every fresh installation; Xray remains available as an explicit user choice.
- Replaced optimistic XTLS/Xray readiness with **strict end-to-end egress verification**. A running local core is no longer treated as a working VPN.
- Made the connection timeline display the **engine that is actually starting**, instead of a hard-coded sing-box label.
- Rebuilt server latency measurement around resolved IPv4 endpoints and three TCP samples, using the median to reject one-off DNS and scheduler spikes.
- Completed Xray rescue-option wiring for custom SNI and TLS/handshake fragmentation.
- Hardened disconnect cleanup across both engines so switching the preference mid-session cannot leave a core running or Windows pointing at Manfaz's local proxy.
- Preserved the original Windows proxy state on normal disconnect, failed verification, engine crash, and application exit.

## Notes

Latency is a TCP handshake estimate to the server endpoint. It is now stable and comparable between repeated Manfaz tests, but it may still differ from ICMP ping or another client's full proxy-delay test because those measure different paths.
